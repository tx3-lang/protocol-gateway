# tx3 0.23 — Upgrade & Per-Protocol Improvement Plan

**Analysis date:** 2026-06-22
**Previous tx3 version (when the protocols were written):** 0.16.4 / 0.17.0
**Current tx3 version:** **0.23.0**

This doc cross-references each protocol's documented limitations/workarounds against the new tx3
features (0.17 → 0.23). Every mapping was **verified against the tx3 v0.23.0 source**
(grammar `tx3.pest`, `crates/tx3-resolver/src/interop.rs`, `crates/tx3-cardano/src/coercion.rs`,
the `examples/` directory, and by compiling test cases with `tx3c`).

> ⚠️ **Verification golden rule:** almost all of these improvements change the generated CBOR or the
> arg wire format. Recompiling is not enough — you must **re-verify byte-for-byte** against the already
> captured reference txs (`*/invoke-args/comparison-report.md`).

## New relevant features (0.17 → 0.23)

| Feature | PR / version | What it unblocks |
|---|---|---|
| **`*` operator (multiply)** | #339 / 0.22.0 | Inline arithmetic in value/datum expressions |
| **`/` operator (divide)** | #340 / 0.22.0 | Same (**integer, floor** division — watch rounding) |
| **Parametric tuples `(A,B)`** | #341 / 0.22.0 | Real `Map<K,(V1,V2)>` — end of the `Bytes 0x00` placeholders |
| **Self-describing argument values** | #343 / 0.23.0 | `interop.rs` rewrite: the resolver accepts **nested structs/enums/lists/tuples/maps as parameters** (previously only Int/Bool/Bytes/Address/UtxoRef) |
| **JSON Schema for complex types** | #337/#338 / 0.22.0 | Typed structured params, surfaced in the TII/OpenRPC |

| **Empty map literals / no panic on unresolved structs** | #328 / 0.19.1 | `{}` is now first-class (quirk #11) |

## Still blocked everywhere (no new feature solves these)

- **Dynamic input/output lists** (batcher/batch txs) — bodega (5 txs), snek-fun (pool fills), vyfi (batcher).
- **Conditional logic `if/when`** — bodega's ADA-vs-token branch.
- **Applying parameters to scripts** (per-launch parameterized policy) — snek-fun mint.
- **Reference-datum fields inside amount expressions** `Ada()/AnyAsset()/min_amount` —
  **verified that #343 does NOT fix this** (it touches `interop.rs`, not amount coercion). Evidence is
  mixed across protocols → requires a direct test before trusting it.
- **Nested Map/List metadata** — **verified NOT fixed** (`tx3-cardano/coercion.rs` still accepts only
  `Number`/`String`/`Bytes`).
- **Exp/ln / fixed-point arithmetic** — snek-fun bonding curve, bodega LMSR price.
- **Reading a UTxO's *value*/balance** (not its datum) — vyfi pool reserves.
- **Extracting the staking key from `Party`** — `signers { Party }` only yields the payment key (fluid-aquarium).

---

## Suggested work order

1. **bodega-market** — highest payoff, no prerequisites.
2. **snek-fun** + **fluid-aquarium** — drop raw CBOR / nested structs (big DX win, low risk).
3. **indigo** — but **re-point to V3 first** (see flag below); only then do tuples + Pyth math apply.
4. **vyfi** — implement `cancel` + inline math.
5. **strike-staking** — quick timestamp win.

## Per protocol

### 🥇 bodega-market — highest payoff

The most workaround-heavy protocol (3 txs split into 6 enum variants, fees pushed to the caller,
redundant fields as params). 8 of 11 txs still can't be implemented due to the batch/conditional ceiling.

- [x] **Collapse the 6 `_yes/_no` txs → 3 txs** taking `candidate: CandidateIdx` as an enum param — `#343` ✅ **DONE 2026-06-22**. Enum arg = tagged `{"struct":{"constructor":N,"fields":[]}}`; cosmetic `674` metadata dropped. Confirmed vs real on-chain NO buy (tx `f57e74aa…`, 5637_SPCX): `pos_candidate=Constr(1)`. Needs a **resolver ≥0.23** (the `mainnet` demeter TRP is too old).
- [~] ~~**Inline `total_lovelace`**~~ — **ATTEMPTED & REVERTED 2026-06-22.** The documented polynomial `buy_amount*unit_price + buy_amount*admin%*1e6/1e4 + batcher + envelope` does NOT reproduce real output: vs tx `f57e74aa…` it over-counts by 894_011 lovelace. `buy_amount*unit_price` overstates the true LMSR cost (stored `unit_price` is a rounded average, not the exact cost basis → needs ln/exp off-chain). `total_lovelace` **stays a caller param**. The old "verified on-chain" comment was circular (back-computed from the same formula). **Lesson: `*`/`/` only help when the polynomial is the actual on-chain math — verify against a REAL tx, not a synthetic fixture.**
- [ ] Pass `OutputRef`/`OptionPkh` as structured params instead of bytes+int pairs — `#343`. **Medium**
- [ ] (Optional) factor the fee formula into a `fn` — `#311`. **Low**

**Still blocked:** the 5 batcher txs (Apply/Reward/Refund/WithdrawFee/Close → dynamic lists), the
ADA-vs-token branch (no `if`), nested metadata, `unit_price` LMSR (needs `ln`/`exp`), and
ProjectInfoDatum fields used in amounts (`pi_envelope_amount`, etc. → remain caller params).

**On-chain re-test:** the enum merge and the `total_lovelace` inline change the CBOR → byte-for-byte diff.

CDP/stability-pool/INDY-staking, 9 txs, ~100% structural match against the **VX** deployment (April 2026).

- [ ] **Real `lockedAmount: Map<Int,Tuple<Int,Int>>`** — today it's a placeholder producing **incorrect CBOR**;

- [ ] Revert the `CdpInterest` → `InterestData` rename (the primitive-prefix bug is fixed). **Low**

> ⚠️ **BLOCKING PREREQUISITE (not language work):** `NEXT-STEPS.md` (2026-06-16) confirms Indigo migrated
> **VX → V3 on 2026-05-28**. The `main.tx3`/`.tii`/`.env.mainnet` point at **dead VX scripts**.

### 🥉 fluid-aquarium — raw CBOR removed ✅ **DONE 2026-06-23**

Babel fees + scheduled txs (FluidTokens), 6 PlutusV3 txs. The caller used to hand-serialize Plutus data
(`staker_redeemer_cbor`, `batcher_addr_cbor`, `tank_datum_cbor`); all of it is now built inline from typed
params. Verified by **TIR diff vs the pre-edit baseline** (`trix inspect tir --tx … --pretty --profile
mainnet`, trix 0.26.2) — `trix invoke` still needs a TTY (CShell wallet) so live-resolve is the user's to run.

- [x] **`staker_redeemer_cbor` → typed `StakerRedeemer`** (#343). The mint redeemer is now
      `StakerRedeemer { owner: owner_address(…), signer_bot: owner_address(…), ref_index, output_staking,
      staking_inputs }`. The old hand-CBOR decoded to exactly this shape; **reconstructing the CBOR from the
      TIR struct + invoke-args is byte-identical** to the on-chain `staker_redeemer_cbor`
      (`d87985d87982…000001`, verified offline with a Plutus-data encoder). Caller now passes 4 hashes + 3
      ints instead of a pre-built blob. On-chain invariant confirmed: `signer_bot` stake hash == staker NFT
      name, owner stake hash == the `signer_hash` signer.
- [x] **`batcher_addr_cbor` → real `PlutusAddress`** (#343) — a **correctness fix**: the old value was the
      placeholder `"00"` (a 1-byte string, never a valid address). Now built inline as
      `owner_address(batcher_payment_hash, batcher_stake_hash)` → `d87982d87981581c…` Constr-address. TIR
      field went from `EvalParam[Bytes]` to the full nested `Struct`.
- [x] **`signatures: []` hardcode → real `List<OracleSignature>` param** (#343). Empty for the Charli3 feed
      (validated via ref input; on-chain `PriceDataCharlie` carries 0 sigs), but the param unblocks the
      signature-bearing variants. **Wire form: a top-level `List` param is a plain JSON array `[]`** — NOT the
      tagged `{"list":[]}` (that fails live-resolve with `expected array for a 'list' argument, got 'object'`;
      the tagged form is only for structs/enums). The TII now carries a real `components.schemas.OracleSignature`
      + an `array` schema. TIR field went from `List:[]` to `EvalParam[List]`.
- [x] **Dropped `empty_bytes` param → `""` literal** (snek-fun parity). The 4 empty `policy`/`name` fields in
      the babel/scheduled tank datums now use the empty-string literal, which lowers to `BoundedBytes([])` =
      CBOR `40` — byte-identical to the empty `Bytes` param. (`0x` empty-hex is still invalid; use `""`.)
- [x] **`fn owner_address(pkh, stake_key) -> PlutusAddress`** (#311). The key-hash-payment + inline-key-hash-stake
      address (`Constr 0 [Constr 0 [pkh], Constr 0 [Constr 0 [Constr 0 [stake]]]]`) is built in 6 places (tank
      owner ×2, destination ×2, scheduled-tx batcher, staker owner+signer_bot). TIR is **identical** to the
      old inline construction — the fn is purely a factoring. Reused the protocol's existing
      `Credential`/`MaybeStakeCred`/`InlineStake`/`PlutusAddress` types (same shape as snek-fun's
      `Credential`/`StakingCred`/`OptionalStake`).
- [x] **`///` doc-comments** added to the 6 txs (the grammar allows `docstring` before `tx`/`party`/`env_field`/
      `parameter` only — **not** before `type` or `fn`; a `///` there is a parse error `expected [doc_line]`).
- [~] ~~**Read oracle/params datum via `datum_is`**~~ — **N/A, nothing to drop.** `min_ada`/`min_to_stake`/
      `address_rewards` only appear in the `ParamsDatum` *type decl* — they are never consumed as fields in any
      tx (the params NFT is just a reference input; tank continuity is `datum: tank_input`). The oracle
      `price`/`valid_from`/`valid_to` feed only the **redeemer** (not amounts, so #13 wouldn't block them) but
      they come from **Charli3's Map-based datum**, which tx3 (positional-only) can't read → they stay params.
- [~] ~~**Inline price math** (`payment_token_qty = dest_ada * denom / price`)~~ — **REJECTED (bodega lesson).**
      No simple `*`/`/` formula reproduces the real `payment_token_qty=1840069` from
      (`dest_ada`,`oracle_price`,`oracle_denominator`); and the true quantity depends on the actual tx fee
      (unknown at build time). Not verifiable against the real tx → stays a caller param.

**Param surface:** raw blobs gone; `stake_fldt` trades 1 CBOR blob for 4 hashes + 3 ints (the #343 trade —
typed structure for a flat-but-honest API). Invoke-args updated for all 5 changed txs (`create_babel_tank.json`
was also stale — it still referenced the removed `tank_datum_cbor`). `.tii` refreshed → `protocols/fluid-aquarium.tii`.

**Live-resolved verification (2026-06-23, `trix invoke --skip-submit --profile mainnet`, toolchain tx3c 0.23.0 /
trix 0.26.2 / dolos 1.3.2):**
- `stake_fldt` ✅ resolved end-to-end; the mint redeemer (`StakerRedeemer`) in the witness set is
  `d87985d87982…000001` — **byte-identical** to the on-chain hand-CBOR (and to the offline reconstruction).
- `create_babel_tank` / `create_scheduled_tank` ✅ resolved; the `""` literals lower to empty bytestrings (CBOR
  `40`) in the `CardanoToken`s, the `fn owner_address` produces the expected `PlutusAddress`
  (`d87982d87981581cf07250ea…d87981d87981d87981581c0423617a…`), and the scheduled amounts/exec-time resolve
  (2_000_000 / 1_000_000 / 1742770540416).
- `consume_oracle` first failed on a **bad invoke-args wire form** (`{"list":[]}` → fixed to `[]`). After
  refreshing its tank + oracle-provider UTxOs it ✅ resolves: `ConsumeOracle` redeemer `Constr(4,…)` +
  `OracleRedeemer{ FeedCharlie(…), signatures: [] }` — **`signatures` lowers to the empty array `80`** (the
  wire-form fix confirmed live); 5 ref inputs incl. the refreshed Charli3 provider `45942e0a…#1`.
- `execute_scheduled` / `withdraw_tank` ✅ resolve once pointed at fresh unspent tanks (the old fixtures'
  tanks were spent — a chain-state issue, never a codegen one). `execute_scheduled`'s batcher field is the
  **real `PlutusAddress`** `d87982d87981581cf07250ea…0423617a…` (was the `"00"` placeholder), and `RewardsAddr`
  resolved from env. `withdraw_tank` → `WithdrawTank` `Constr(2,[])`.

**Net: all 6 txs live-resolve end-to-end.** Fresh tank UTxOs were found via Koios `credential_utxos` on the
tank validator `f9724c47…` (helper in `scratchpad`); the refreshed fixtures are build/codegen tests
(`--skip-submit` doesn't run validators) and honor the balance constraints (`execute_scheduled`:
`dest_ada+reward_ada = tank_lov`; `consume_oracle`: `tank_return_ada+payment_ada = tank_lov`).

**Still blocked:** staking-key signer (`signer_hash`/`batcher_signer_hash` stay `Bytes` — `signers{}` only
yields the payment key); Charli3's **Map**-based oracle datum (tx3 is positional-only → likely unreadable even
with `datum_is`; the protocol's *own* positional datums would be readable, but none of their fields are needed);
collateral must be an ADA-only UTxO.

### snek-fun — DX + modeling fidelity ✅ **DONE 2026-06-23**

Launchpad/bonding-curve, 4 txs, byte-match with mainnet (Poppy/LAIKA). The on-chain shapes are correct;
what was open was caller ergonomics and modeling fidelity. All five planned items landed; verified by
**TIR diff vs the pre-edit baseline** (`trix inspect tir --profile mainnet`, trix 0.26.2) **and by
live-resolved CBOR** (`trix invoke --skip-submit --profile mainnet`; the mainnet TRP is ≥0.23 — see
verification note below).

- [x] **Unwound the 4-struct address chain** (`CardanoAddress/OrderPayment/OrderStakeCred/OrderStakeJust`)
      → proper enums `Credential` (PubKey/Script) · `StakingCred` (Hash) · `OptionalStake` (Some/None) ·
      `PlutusAddress` — `#343` ✅. Constructed inline through a shared `fn owner_address(pkh, stake_key)`.
      **TIR is byte-identical to the old chain** (`Constr 0 [Constr 0 [pkh], Constr 0 [Constr 0 [Constr 0 [stake]]]]`).
      Naming gotcha: a custom type **cannot** be called `Address` — that's a tx3 primitive (`primitive_type`
      is tried before `custom_type`); used `PlutusAddress`.
- [x] **Inlined the verifiable escrows + supply split** — `*`/`/`/`-` (`#339/#340`). Dropped 2 params + 1 env var:
  - `place_buy_order`: `total_escrow_ada` param → `Ada(ada_input + executor_fee + min_order_out_ada)` (env vars
    work in amount expressions; verified 69M+1.5M+1.1M = **71_600_000** vs the real Poppy buy).
  - `place_sell_order`: `sell_escrow_ada` env var → `Ada(executor_fee + min_order_out_ada)` (= **2_600_000**).
  - `launch_token`: `curve_tokens_remaining` param → `token_emission - initial_buy_tokens` (Poppy:
    1_000_000_000 − 50_047_569 = **949_952_431**, byte-match). The other `launch_token` ADA figures
    (`launch_fee_ada`, `pool_seed_ada`, `metadata_min_ada`, `creator_min_ada`, `ada_cap_thresh_for_pool`)
    **stay params** — they're independent min-ADA/fee/curve values, not derivable on-chain (bodega lesson).
- [x] **Grouped the launch_token param surface into records** — `#337/#338/#343`. 9 metadata/socials scalars
      → one `meta: LaunchMetadata` (with nested `socials: Socials`); 2 creator scalars → `author: PoolAuthor`
      (whole-value substitution, no field access). The TII now carries real `components.schemas`
      (`LaunchMetadata` → `$ref` `Socials`, `PoolAuthor`). MetadataDatum TIR unchanged in shape: fields lower to
      `Property(meta, i)` at the same Constr positions; `author` substitutes whole. Field access on struct params
      in datum position is the verified `#343` path (mirrors `examples/complex_type_params.tx3` `order.price`).
      **Left token-identity + ADA-amount params flat** (used pervasively / in amount expressions) — low value,
      and amount-expression field access on struct params is not resolve-testable headless.
- [x] **`fn owner_address`** for the duplicated buy/sell owner datum — `#311`. Returns `PlutusAddress`; TIR identical.
- [x] **Dropped `empty_bytes`** (3 txs) → the empty **string literal `""`**, which the analyzer types as `Bytes`
      (`ast.rs:844`) and lowers to `BoundedBytes([])` = CBOR `40` (`compile/plutus_data.rs:146`
      `String(x) => x.as_bytes().as_data()`) — byte-identical to the old empty-Bytes param. `0x` (empty hex) is
      still invalid (grammar requires ≥1 digit); `""` is the literal to use.

**TIR verification result:** `cancel_order` **fully identical**; buy/sell differ **only** by the escrow `Add` and
`empty_bytes`→`String ""`; `launch_token` inputs/mints/fees + outputs 1/3/4 identical, the curve `Sub`, the
`quote_asset` empty→`""`, and the MetadataDatum grouping the only diffs (PoolDatum 8/9 fields untouched). Every
change preserves Constr nesting / field order; the `String ""` and `Add`/`Sub` are byte-equivalent to the
pre-summed params. Invoke-args updated (`meta`/`author` use the tagged wire form
`{"struct":{"constructor":0,"fields":[…]}}`, scalars stay bare); `.env.mainnet` lost `SELL_ESCROW_ADA`;
`protocols/snek-fun.tii` refreshed.

**Live-resolved verification (2026-06-23, mainnet TRP confirmed ≥0.23):** the `.tii` resolves end-to-end on the
deployed resolver — the earlier "TRP too old" concern is **resolved** (the mainnet TRP now accepts the
`+`/`-` arithmetic and the `#343` self-describing params).
- `place_buy_order` rebuilt with Poppy's exact values → order datum **blake2b-256 = `da37…ec677`, byte-identical to
  the on-chain Poppy order** (`5322698e…#0`).
- `launch_token` resolved with a live seed (re-derived `token_policy`/`token_script`) → 5 outputs built; the
  generated `PoolDatum` is **byte-identical to the real Poppy launch (`7e7161f3…`) in 7 of 9 fields**
  (quote_asset/a_num/b_num/executor/ada_cap_thresh/factory_witness/pool_witness); only `pool_nft_name` and
  `base_asset` differ (seed/token-specific, unavoidable). The `-` supply split resolved to **949_952_431**, the
  `""` literals to empty byte strings, and `meta`/`author` (`Property(meta, i)` + whole-value) into the correct
  `MetadataDatum`. min-ADA outputs (metadata 2_534_280 · fee 1_825_000 · dev-buy 1_206_800) byte-match Poppy.

> Note: a real launch can't be byte-matched the way the buy was — the buy's input is fungible ADA, but the launch
> seed is a specific consumed UTxO that parameterises the policy, so it's shape-match only. Also: on-chain byte
> strings >64 B are chunked (indefinite); tx3 emits short fields definite — a CBOR length artifact, not a shape diff.

**Still blocked:** pool fills (batcher's dynamic indices), per-launch parameterized mint policy
(no script-parameter application), exponential curve `a*exp(b*sold)` (no exp/fixed-point).
